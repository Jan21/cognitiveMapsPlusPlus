CognitiveMaps++ · distance model

The recall-flow integrator, explained end to end

It predicts how many BFS steps separate two states of a switchyard world. The trick: it doesn't regress a distance, it walks the latent state from start toward goal and adds up how far it travelled. Distance is a path length, integrated step by step.

D(s,g) = softplus(scale) · Σt=1..T Σi∈state ‖ zi(t) − zi(t−1) ‖
Every symbol on this line is defined below. The amber double-sum is the whole idea.

THE IDEADistance = the length of the path the state walks

Give the model a start state and a goal state on the same map. It encodes both, then runs a small transformer T times over (the same weights each time). At every pass the state tokens move a little in latent space. The model measures the length of each little move and sums them over all passes. That running total, scaled by one positive number, is the predicted distance.

Intuition: a near pair needs the state to barely move → small total → small distance. A far pair forces the state to travel a long way through latent space → large total → large distance. It is a path integral, not a lookup.

accumulated Σ‖Δz‖ = 0.0  →  D≈0

Toggle near vs far: the same machinery, a longer walk, a bigger sum. The dot's trajectory is a stand-in for the state tokens moving each recall step; the amber trail is the quantity being accumulated.

STEP 1 · PERCEPTIONFrom a game state to a bag of tokens

The world is a switchyard: a worker pushes a crate on a G×G grid past gates that are opened by levers (wired to gates) and a plate. A state x is the worker cell, the crate cell, and the gate bits. The encoder turns one state into NTOK tokens, each a vector in R^d — one token per moving/structural piece of the scene.

renderstate → picture(B, 8, G, G)

Draw the whole scene as an 8-channel image

Channels: walls · worker · crate · gate cells · gate-open flag · levers · plate · chute. No coordinates are handed in as numbers — the model must see where things are.

CNN2 conv layers→ (B, d, G, G)

A small convolutional net reads the picture

Conv 8→64 → ReLU → Conv 64→d → ReLU. Output is a d-dim feature vector at every grid cell. Two layers is the sweet spot; deeper hurts.

x-attn readfind the agents→ worker, crate

Two query tokens cross-attend the feature map

One learned query for the worker, one for the crate. Each attends over all G×G feature cells and pulls out its own token — unsupervised: the model is never told which cell is the worker. It learns the binding from the distance signal alone.

assembleNTOK tokens(B, NTOK, d)

Add the structural tokens

Worker · crate · gate-bits · one token per gate · per lever (carrying its wiring) · plate · chute · a pooled wall token. Each also gets a role-id embedding. NTOK = 3 + ngate + nlever + 3. This bag of tokens is the state.

why images

An easier variant (bmask) hands the exact worker/crate cell straight in. The convolutional path deliberately gives that up — it reads entities out of pixels, the realistic setting. That is why it scores a bit lower yet is the interesting model.

STEP 2 · THE FLOWWalk the state, and re-inject the goal every step

Now three copies of the token bag are stacked into one sequence of 3·NTOK tokens:

zstate  + role 0  the part that MOVES 
zgoal  + role 1 zstart-anchor  + role 2  re-injected unchanged every pass = “recall” 

Role embeddings tell the transformer which copy is which. Only the first block (state) is allowed to evolve; the goal and the original start are pasted back in at the top of every loop so the network can never “forget” its destination or its origin.

Then the loop runs T times (default T = 14) with a single weight-shared transformer Block (a few pre-norm layers):

# tok = [ z_state ; z_goal ; z_anchor ]      # (B, 3·NTOK, d)
cost = 0
for t in range(T):
    z    = Block(tok)                          # one shared step of "flow"
    cost = cost + (z[:NTOK] - tok[:NTOK]).norm(dim=-1).sum(-1)   # add per-token move length
    tok  = [ z[:NTOK] ; z_goal ; z_anchor ]    # keep evolved state, RECALL goal+start

D = softplus(scale) * cost                       # one positive scalar → BFS steps

Read the amber line as the thesis: (z[:NTOK] − tok[:NTOK]) is how far each state token moved this pass; .norm(dim=-1) is the length of that move; .sum(-1) adds over the NTOK tokens; the loop adds over the T passes. That double sum is ΣtΣi‖Δz‖ — the accumulated arc length. softplus(scale) is the one learned knob that keeps D ≥ 0 and converts latent length into BFS-step units.

STEP 3 · LEARNINGOne loss, the true shortest path

For each training pair the ground truth is the BFS geodesic: the real minimum number of legal moves from s to g on that map (respecting walls, gates, wiring, crate-pushing). The whole stack — CNN, cross-attention read, transformer, scale — is trained end to end with a single smooth-L1 regression:

loss = smooth_l1( D(s, g, m) , bfs_distance(s, g, m) )

No path supervision, no binding labels, no per-step targets. The model is only ever told the total distance, and it discovers on its own that the honest way to produce it is to route the latent state and pay for the trip. Pairs are sampled across 150 training maps, stratified by distance; the held-out 50 maps (new layouts and new wiring) test whether it learned the mechanism rather than the maps.

why it must accumulate, not guess

A plain regressor could memorise “these two look ~8 apart.” The accumulator can't shortcut: the only way to output a large number is to actually move the state far over the T passes. That structural honesty is what lets it — in the right regime — extrapolate to distances longer than any it was trained on.
