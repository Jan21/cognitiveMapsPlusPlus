Teaching a network to judge how far apart two situations are

This page explains, from the ground up, one focused experiment: can a neural network learn to estimate the true "walking distance" between two configurations of a small world — and, crucially, can it still do that for configurations whose rules it never saw during training? No prior background is assumed.

01The little world, and what a "state" is

Everything happens on a small square grid — think of a 6×6 chessboard. On that board sit a handful of tokens we call agents. A single snapshot of the board — where every agent is standing, together with the rules currently in force — is what we call a state.

Two kinds of rules can be attached to each state, and they are what make the world interesting:

  • Mobility. Each agent has a movement rule. It might be free to move in all four directions, or restricted to only horizontal moves, or only vertical moves, or frozen in place entirely.
  • Links. Some pairs of agents can be chained together. Chained agents are no longer independent: they can only move as a single rigid block, all shifting in the same direction at the same time, or not at all.

Linking matters because it makes the rules interact. Two unchained, free agents can wander independently. Chain them, and suddenly the pair behaves like one object — the ways the board can change collapse. This coupling is the whole point: the difficulty of getting from one board to another depends on the specific combination of mobility rules and links currently active.

02What we mean by distance

Given two states — a starting board and a goal board — the distance between them is simply the smallest number of legal moves needed to turn the first into the second. This is an ordinary notion of "how far apart," the same idea as counting the fewest steps through a maze. Because the legal moves depend on the mobility and link rules, the distance is not just about how far the pieces have to travel across the grid; it also reflects how much the rules get in the way.

We can always compute this true distance exactly with a classic shortest-path search (a breadth-first search over legal moves). That exact distance is the answer key. The entire task for the network is to reproduce that answer key on its own, from looking at the two boards.

03The model, and the idea behind it

Rather than guessing a distance in one shot, the model estimates it the way you might pace out a route: it takes a number of small internal "steps" and adds up how far it moved at each one. Concretely, the network holds an internal representation of the current situation and repeatedly nudges it, over a fixed number of rounds, always keeping the starting board and the goal board in view. The total distance it reports is the sum of how much its internal representation shifted across all those rounds, scaled by a single learned number.

start with:  [ start · goal · start ]
repeat T rounds:  move the representation a little →  add that movement to a running total
            then remind it of the goal and the start again
distance = (learned scale) × (total movement)

Two design choices are worth calling out in plain terms. First, the distance is an accumulated path length rather than a single number read off at the end — it is built up step by step, which mirrors how real distances add up along a route. Second, the goal and the original start are fed back in at every round; this "reminder" keeps the process anchored, so it never loses track of where it began or where it is trying to end up. The network is trained by comparing its reported distance to the true shortest-path distance and nudging its weights to close the gap.

04Two ways of showing the model a state

How the model is told where the agents are turns out to matter, so we compare two setups of increasing realism.

  • Factored input. The model is handed each agent's position directly, as clean numbers. This is the easy, idealized case — there is no perception problem to solve.
  • Image input. The agents are painted onto a grid picture, and the model has to figure out from that picture where each agent is. This is closer to how a real system would receive the world: as a rendered image rather than a tidy list. Reading positions off a shared picture is a genuine extra challenge, because several agents can appear together and the model must still tell them apart. We use a picture format designed so no agent is ever hidden behind another, which is what makes it possible for the model to learn this on its own.

In both cases, the mobility and link rules are supplied as a separate compact summary rather than drawn into the picture; only the positions go through the perception step.

05How we measure success: accuracy and generalization

We report three complementary numbers. The first two are about accuracy — how close the model's distances are to the truth. The third is a simpler sanity check.

  • Distance error (MAE). On average, how far off is the predicted distance from the true distance, measured in number-of-moves? Smaller is better; zero would be perfect. A value of, say, 0.1 means the model is typically within a tenth of a move of the exact answer.
  • Distance correlation. Across many pairs of states, do the predicted distances rise and fall in step with the true distances? A value near 1.0 means the model orders things correctly even where the exact magnitude drifts.
  • Move-ranking check. For a given board, a legal one-step move should look closer than an illegal move that breaks the rules. This measures how often the model gets that ordering right — a quick test that it has actually internalized the rules rather than just the raw grid geometry.

The important distinction runs through all of these: we always measure them twice — once on configurations drawn from the same pool the model trained on (this is accuracy), and once on configurations that were deliberately held out of training (this is generalization). The gap between the two is what tells us whether the model learned the underlying rules or merely memorized the cases it saw.

06The kinds of generalization we test

Not all "held-out" cases are equally hard. We use three progressively more demanding splits, because each probes a different way the model might fail to generalize.

SplitTrained onTested onWhat it asks
combomost rule combinationsa few held-out rule combinations, in the same overall difficulty rangeCan it fill in gaps between things it has seen? (interpolation)
links2states with at most one linkstates with two or more links at onceCan it handle richer coupling it never saw? (structural extrapolation)
dofhiless flexible statesthe most flexible states, never seenCan it extend to a difficulty level beyond its training range? (value extrapolation)

The first split is the gentlest: the test cases sit among familiar ones. The second forces the model to reason about combinations of links it was never shown, which is where memorization tends to break down. The third asks it to step outside the range of situations it ever encountered, which is the hardest thing to ask of any learned model.

07Results

Accuracy: the model learns distance well

On states drawn from the training distribution, the model reproduces the true shortest-path distance closely. With clean or lossless input it lands within roughly a tenth of a move of the exact answer, which is very tight given that distances range up to a dozen moves.

Input formattypical distance error (moves)reading
lossless canvas≈ 0.09essentially exact
factored (clean positions)≈ 0.1–0.2very accurate
image, learned perception≈ 0.3 (falling with training)harder, but keeps improving as it learns to read the picture

The pattern is intuitive. When positions are handed over cleanly, learning the distance is straightforward. When the model must instead read positions from a rendered image, the same accuracy is reachable but takes more training, because it first has to solve the perception problem of telling the agents apart on a shared picture. The error keeps dropping the longer it trains, which is the encouraging sign that nothing is fundamentally blocking it.

What the results say so far

  • The core ability is real. A network trained only to match shortest-path distances learns to do so accurately, to within about a tenth of a move on familiar configurations.
  • Perception is a surmountable cost, not a wall. Moving from clean inputs to a rendered image makes the task harder and slower, but the model still gets there — accuracy improves steadily as it learns to read the picture.
  • Generalization is the headline question, and it is being quantified now. The experiment is specifically designed to separate "learned the rules" from "memorized the examples," across three increasingly demanding held-out splits; those precise numbers will appear above once the queued run finishes.
