Reading degrees of freedom from a learned distance

A state made of agents whose freedom is gated by a key. We train a distance from local moves only, then ask its own local geometry how many degrees of freedom each state has. It answers correctly across a 1-to-5 ladder, with nothing telling the model which factor is the key.

the result

Measured dimension tracks the true DOF

At a state where key = m, exactly 1 + m agents can move, so the true local dimension is 1 + m. The learned distance, measured by its volume-growth dimension (VGT), recovers this ladder from 1 to 5.

1 data

Agents on rings, freed by a gated key

A state is (pos_0, ..., pos_4, key). Each of the 5 agents lives on a 48-node ring (a one-dimensional component). The key runs 0 to 4. Agent 0 is always free (the mover); agent j can move only when key ≥ j. So the key sets how many agents are free, and therefore the local dimension.

The key is gated: it can only be changed while the mover stands on one control cell. So at a generic state you cannot change the key, and the local neighbourhood stays locked inside its own stratum. This is what keeps other strata from leaking into the dimension measurement. Everything is a factored index vector, no images.

2 architecture

A gated sum of per-component distances, with the key undisclosed

The distance is learned. Each component has its own embedding, and the distance is a weighted sum of per-component distances. The weights come from a gate that reads a pooled context over all components at once, so the key is never singled out in the architecture:

d(x, y) = Σagents i wi · ∥ ei(posix) − ei(posiy) ∥ + wkey · ∥ ekey(keyx) − ekey(keyy) ∥ wi = softplus( gate( [ agent i's token , pooled context over ALL components ] ) )

Because the gate only sees the key blended into a pooled context (never flagged as "the key"), the model has to discover that the key gates the agents. It does: after training, moving a free agent one step costs about 1, while moving a frozen agent costs 30 or more. The gate learned to make frozen coordinates expensive, on its own.

3 training

Multi-scale isometry, plus repulsion

Training uses local structure only, no shortest-path labels. Two terms:

isometry move each FREE agent by a random k in [−K, K]; target = Σ |k| → loss += ( d(x, x') − Σ|k| )2 repel illegal move (a frozen agent) or a random state → loss += softplus( margin − d )

The isometry term is the important one. "Neighbour at one step equals distance one" alone is not enough: it pins the first step and pushes everything else to the margin, leaving no intermediate scales for a volume-growth estimator to read. Training k steps to distance k across a range of k makes the embedding locally isometric, so a ball of radius r genuinely contains an rd-sized set. The repulsion term is what keeps the strata apart: moving a frozen agent is pushed far, so it never enters the local neighbourhood.

What the trained metric looks like A free agent's one-step move reads about 1; a frozen agent's one-step move reads 30 to 120. The metric is both locally isometric along the free directions and sharply stratified across the frozen ones.

4 dimension estimation

Sample along the stratum, then measure volume growth

To read the local dimension at a probe we need points that lie on its stratum. We let the model find them, then count how fast neighbours accumulate.

Gate-guided sampling

  • Ask the model which agents are free. Move each agent one step and read the distance: free agents give ~1, frozen agents give ~30+. This uses only the learned distance, no graph and no key.
  • Jitter only the free agents. Perturb the free agents' positions, hold the frozen ones fixed. Every pool point then lies on the stratum. (Jittering all agents instead would place almost no points on a low-dimensional stratum embedded in many frozen coordinates.)

VGT: the volume-growth dimension

For a d-dimensional manifold the number of points within radius r grows as count(r) ~ rd. So the local dimension is the slope of log(count) against log(radius), read over the on-stratum pool. Counting within a ball is tolerant of the tied distances that come from a discrete lattice, which is why this estimator is the right one here.

dimension = slope of log( number of neighbours within radius r ) vs log( r )
One honest limit This is a finite-sample estimator, so the highest dimensions read a little low (DOF 5 comes out near 4.1). The ladder stays monotone and clearly separated; the ceiling is a property of measuring high-dimensional volume with finite points, not of the model, whose metric is correct.

The recipe

Multi-scale isometry training (so the metric has intermediate scales) plus gate-guided on-stratum sampling (so the pool lies on the stratum) plus the volume-growth dimension (so ties do not matter): together they read the degrees of freedom of a state straight from a learned distance, with the gating structure discovered rather than supplied.
