Learning distances on guarded graphs

A state made of components, each with its own graph, where moving one component may require another to be in the right place first. We wanted an embedding distance that reflects the real shortest path, detours included, and learns it from examples. It works: distance as a sum of gated pieces, one piece per move and one per detour.

The problem

Components, internal graphs, and guarded edges

A state is a tuple (s_0, ..., s_F). Each component has its own graph of legal internal moves: a chain, a cycle, a 2-D grid, anything. The twist: an internal edge of one component is traversable only if a guard holds, meaning some other component sits in an enabling set of its own states. The classic case: an agent can move only while its knob reads 5.

That makes the true geodesic piecewise with detours. To move a guarded component you first steer its guard into an enabling state, move, and usually steer it back; and that enabling step may itself be guarded, so detours can nest. The distance has to account for all of it.

How the attention works

Distance as a sum of gated pieces

The head never runs a search. It builds the distance from small learned terms, each a "piece" of the path, and adds them:

d(x, y) = Σcomponents f gate·movef(sfx, sfy) + Σdeps f←g gate·detourf←g(sgx, sgy) gate = sigmoid(·) — INDEPENDENT, not softmax

movef learns the internal geodesic of component f (works for a cycle or a grid, not just a line). detourf←g learns the cost to bring guard component g into an enabling state and back. The gates decide which pieces are live for this pair of states.

Why sigmoid, not softmax Softmax normalizes the weights to sum to one, so the output is a weighted average and can never exceed its largest term: it cannot build a detour. Independent sigmoid gates let the pieces accumulate, so a dial-up plus a move plus a dial-back stack into one distance. This single change is what made the attention work.

On the two-chain warm-up (position plus a knob that gates it), this reproduces the exact detour geodesic: (0,0)→(5,0) = dial up 5 + move 5 + dial back 5 = 15, with overall RMSE 0.00.

Accuracy the good result

Near-exact on held-out pairs, across geometries

We enumerate each space, compute the exact all-pairs geodesic, train on 70% of pairs, and score the held-out 30%. Compared against a free per-state embedding with no structure (a lookup table trained on the same targets):

The dependency graph is discovered, not wired in

We do not tell the head which component guards which. It gets a detour piece for every ordered pair, and the gates learn which are real. This "learn the dependencies" version matches the wired one on held-out fit (grid 0.01, nested 0.01). The only structural input is the factorization itself, which the state already provides.

Can we read the structure back out? the hard part

The distance is right, but it hides how

Getting the distance right is not the same as exposing the guard graph. We tried to recover the true dependencies from the trained pieces, and most attempts failed for the same reason:

attemptoutcome
read each piece's contributionsmears: transitive and spurious pieces both carry cost
L1 / group sparsityfails: cost just relocates into the move-terms
ablate a piece, no retrainconfounded: parked cost looks necessary
leave-one-out + retrain, flexible headnothing is necessary: fully non-identifiable
+ component-local move-terms (rigid)still nothing: free gates re-route across pieces
+ gates tied to each piece's own move (constrained)recovers A←B and B←C exactly

Why it hides. The distance is a sum, so cost is fungible: many different assignments of cost to pieces produce the same total. A flexible head has no reason to prefer the true decomposition. Only when each piece is constrained to a unique role, meaning a component-local move-term plus a detour gate that fires only when that component moves, does the sum become identifiable.

The constrained head recovers the guard graph

Leave-one-out retraining on the constrained head: forbid one dependency, retrain, and measure how much held-out error it cannot recover. The two necessary dependencies are exactly the true direct guards.

The tradeoff the real conclusion

Accuracy or interpretability, pick a point on the knob

Making the head identifiable costs expressiveness, so it only approximates the geodesic. This is the same "piecewise approximation, sometimes not enough pieces" picture from the start, now made precise:

The bottom line From geodesic distances alone you cannot have both. The accurate model has many equivalent internal decompositions; forcing a single interpretable one costs accuracy. Which side of the knob you want depends on the goal: accurate navigation, or a readable dependency graph.

In one paragraph

What we learned

An embedding distance built as a sum of independently-gated pieces, one per component-move and one per guard-detour, reproduces the shortest-path geodesic of a guarded product graph, across cyclic and grid internal geometries and nested guards, to held-out RMSE around 0.01, and it discovers which dependencies exist rather than being told. Reading the guard graph back out is a separate problem: the sum is non-identifiable, so recovery needs a constrained, uniquely-decomposable head, which recovers the true guards at the cost of some distance accuracy. Accuracy and interpretability sit at opposite ends of one knob.
